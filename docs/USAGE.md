# Local Token usage

This feature supports Antigravity desktop and its standalone IDE. Each uses its own data directory and local trajectories. The CLI adapter is unchanged.

Open the database/cache icon, then **View token usage**:
- **Activity tab:** Daily and weekly contribution heatmaps with hover counts and year selection.
- **Usage details tab:**
  - **Account scope selector (`#account-switcher`):** Positioned on the right side of the tabs bar (`.tabs-bar`) when multiple accounts exist; switch between individual local accounts (`accounts-v1.json` / optional local `.data/usage-accounts.local.json`) or **All Accounts (Aggregated)** across every dimension including **Project Stats**.
  - **Dimension & model grouping controls:** Switch between **By Model** (`按模型统计`), **By User** (`按用户统计`), and **Project Stats** (`项目统计` — `src/telemetry/ledger/project-stats.ts`). In the model view, switch between **Simple** (`简易`, default) and **Detailed** (`详细`): Simple mode normalizes and groups model variant suffixes and casing via `baseModelName()` (while preserving `Orchestrator (Argon)`), and clicking or pressing Enter/Space on any grouped table row (`tr.model-group-row`) expands inline per-variant breakdown rows (`tr.model-variant-row`).
  - **Project Stats & on-demand conversation drilldown (`src/ui/usage-modal/project-detail.ts`):** Level-1 (`queryProjectUsageOverview`) aggregates workspace URIs, worktrees, parent conversation chains, Antigravity CLI sessions (`default-cli-project`), general conversations (`outside-of-project`), and remote sessions (`remote:*`), returning per-project totals and daily stacked bars. Selecting a project loads Level-2 (`queryProjectConversationDetail`) on demand with horizontal main-session bars, expandable subagent rows, and a synced SVG donut chart.
  - **Date range & single-bar drilldown:** Switch between **Day**, **Week**, **Month**, and **Custom** date range (`<input type="date">` with adaptive horizontal scrolling for ranges `> 31` days). Clicking a bar highlights that bucket (`.selected`) and filters the breakdown table (and selected project detail) to that period, with a one-click reset.
  - **24-hour trend line chart (`Hourly trend`):** Collapsible interactive SVG 24-point smooth Catmull-Rom / Bezier spline chart with gradient area fill, crosshair inspection, non-negative geometric clamping, and **Period total** (`区间汇总`) vs. **Today** (`今日`) views (hidden when **Project Stats** is active).
  - **Independent `Aa` font-scale popover (`src/ui/shared/font-popover.ts`):** Customize font scaling (`80%`–`150%` in 5% steppers or direct input) independently for the Usage modal (`usageFontScale`), Sidebar (`sidebarFontScale`), and Bottom inline card (`inlineFontScale`), synced across restarts via `preferences.json`.
  - **Remote Project Manual Usage (`+ Remote Usage`):** Create, edit, or delete manual token usage entries for mobile or external remote sessions, persisted as SHA-256 hashed JSON records across both the CDP bridge and Electron IPC.

On first opening, a compact introduction explains local history import, missing/deleted history, the difference from account billing, `Asia/Shanghai` (UTC+8) date boundaries, and local-only numeric storage. **Got it** saves acknowledgment independently of language and theme.

The window uses a top-layer popover with dialog semantics, a backdrop, and explicit keyboard/focus containment (`src/ui/usage-modal/`), avoiding Chromium's whole-document modal inertness stalls on long chats. Model and user colors are synthesized dynamically from the active host accent and background (`src/shared/color.ts` and `src/ui/usage-modal/palette.ts`) with at least 3:1 contrast against the background.

## Accounting & multi-account isolation

- `Total = uncached input + cache reads + cache writes + output` (output includes thinking tokens).
- Token usage is independent of TPS timing-quality exclusions.
- Request creation time determines the date (falling back to the matching planner step's creation time); undated requests contribute only to the all-time total.
- Date grouping uses `Asia/Shanghai` (UTC+8) and Monday-start weeks.
- **Strict per-account ownership (`ownership-v1.json`):** Both live ingestion (`DesktopUsage.ingest`), historical backfill (`DesktopUsage.runSync`), and project statistics (`buildScopeFilePlan` / `loadSharedFileSummariesJs` in `src/telemetry/ledger/project-stats.ts`) enforce per-account conversation ownership (`registerOwnership`, `otherScopeFiles`, `inspectOtherAccounts`, primary-account tie-breaking via `buildPrimaryPicker`, and time-bounded splitting of cross-account active continuations). Switching `#account-switcher` scopes (`All Accounts (Aggregated)` or a single account) updates `#project-scope-note` and re-queries `getProjectUsage` / `getProjectDetail` under the selected `viewScope` so single-account and aggregated project totals match `UsageLedger.summary()` without cross-account leakage. `tools/reconcile-usage-ledger.mjs` (`dry-run` / `--apply`) is also provided to audit and clean any historical duplicate ledger files with conservation verification.
- **Incremental `fileIndex`, native binary caches (`ledger-compact-v1.bin`, `project-ledger-v1.bin`), `project-meta-v1.json` & fast timezone mapping (`v0.11.0`–`v0.12.3`):** `UsageLedger` maintains an in-memory `fileIndex` (`mtime + size` with `keyVersions` concurrency guards), separated `writeQueue`, and dedicated `projectDirtyRelPaths` invalidation so `summary()` and `queryProjectUsageOverview()` only re-parse changed `<sha256>.json` files. When the Rust native addon (`pulse-accel`) is enabled, `queryUsageLedgerSummaryJson` (`ledger-compact-v1.bin` + `LEDGER_MEM_CACHE`) and `readLedgerProjectSummariesJson` (`project-ledger-v1.bin` + `PROJECT_MEM_CACHE`) stream-parse records off V8 heap in parallel. Conversation titles, workspace URIs, parent links, and agent roles from `conversation_summaries.db` (stat-validated on both `.db` and `.db-wal`) and `store.rawSummaries` are persisted non-destructively in `project-meta-v1.json` (`persistProjectMetaFromRawSummaries`) so project mappings survive SQLite truncation or deletion. `src/telemetry/ledger/timezone.ts` (`dateTimeParts`, `resolveTimeZoneSpec`, `formatCivilDateFromDays`) uses precomputed UTC/UTC+8/UTC+9 offsets and binary-searched DST transition tables instead of repeated `Intl.DateTimeFormat().formatToParts()` calls. `DesktopUsage.runSync()` flushes `backfill-v1.json` checkpoints once per 3-second batch slice rather than inside the inner conversation loop.
- History discovery scans candidate IDs from local `conversations/*.db` and `brain/<conversation-id>` directories plus the authenticated local API. Files only identify candidates; Token counters always come from the authenticated local API or explicit manual entries.
- Only available local records can be recovered. Deleting a conversation does not subtract already recorded consumption. This is observed local usage, not provider billing.

## Storage and privacy

The `usage-v1` directory is separate from `history-v1` (latest conversation statistics) and `timeline-v1` (opt-in structural call timeline). It stores request time, model, Token counters, and hashed request/conversation/account identifiers. Prompts, replies, and credentials are never stored. Personal account display labels can be configured locally in gitignored `.data/usage-accounts.local.json` and are never embedded in source code or release packages.

- **Desktop path:** `~/.gemini/antigravity/sidecar_data/antigravity-pulse/panel/data/usage-v1/`
- **IDE path:** `User/globalStorage/shzbz.antigrative-dashboard-ide/usage-v1/` under the IDE profile (see `ide/README.md` if migrating from `you-should-know-me.antigrative-dashboard-ide`).
